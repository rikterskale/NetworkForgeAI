NetworkForgeAI — 10/10 Remediation Fix List
================================================

Purpose
-------
This document lists the fixes required to move the project’s assessed areas
toward a defensible 10/10 standard.


P0 FIXES — FOUNDATIONAL
-----------------------

1. Create one canonical runtime configuration model.
   - Load Settings() for every CLI scan.
   - Make CLI flags explicit overrides over environment values.
   - Wire TARGET_SCOPE, APPROVAL_MODE, REPORT_OUTPUT_DIR,
     MAX_CONCURRENT_AGENTS, CI_MODE, logging, and session settings into
     runtime behavior.
   - Add configuration-precedence tests.

2. Unify approval policy enforcement.
   - Define policy by action type: passive, active, authenticated,
     exploitative, and destructive.
   - Apply the same rules to direct CLI tools, agents, validation runners,
     dashboard actions, and integrations.
   - Ensure medium-risk direct CLI scans cannot bypass approval where policy
     requires it.
   - Centralize justification enforcement.

3. Establish authoritative dependency management.
   - Make pyproject.toml the source of truth.
   - Remove unnecessary packages such as asyncio from requirements.txt.
   - Generate or validate Docker requirements from package metadata.
   - Add dependency constraints or lock files.
   - Test clean installs from both wheel and source.

4. Add real end-to-end testing.
   - Use local deterministic targets only.
   - Test real scanner binaries in a fixture container.
   - Exercise tool -> agent -> approval -> sandbox -> finding -> report.
   - Test dashboard HTTP endpoints using an ASGI client.
   - Test restart and state recovery.

5. Replace feature claims with maturity levels.
   - Separate implemented, unit-tested, integration-tested,
     end-to-end-tested, and production-hardened.
   - Update README, capability register, changelog, and historical phase
     documents.
   - Remove or qualify vendor-grade and production-ready claims without
     evidence.


OVERALL PROJECT — 10/10
-----------------------

- Add a formal threat model.
- Add a security architecture review and threat-model document.
- Define supported deployment profiles.
- Publish compatibility guarantees for Python, Docker, scanners, and LLM
  providers.
- Add release management, semantic versioning, migration notes, and rollback
  procedures.
- Add signed releases, SBOMs, provenance attestations, and verified build
  artifacts.
- Establish explicit SLAs/SLOs for scans, approvals, failures, and report
  durability.
- Add a public quality dashboard tracking coverage, security findings, flaky
  tests, and integration status.


SCOPE AND APPROVAL SAFETY — 10/10
---------------------------------

- Make all active actions pass through one policy engine.
- Enforce persistent environment scope in addition to one-run CLI scope.
- Normalize and canonicalize targets before comparison:
  DNS casing, URLs and ports, IPv4/IPv6, CIDR boundaries, IDNs, redirects,
  and wildcard semantics.
- Prevent DNS rebinding and target-resolution drift.
- Bind approvals to exact target, exact command digest, exact tool version,
  exact scope, operator identity, and expiration time.
- Require explicit justification for every exploitation and post-exploitation
  action.
- Add two-person approval for destructive or critical actions.
- Add approval replay protection.
- Add immutable, hash-verifiable audit logs.
- Add audit-log export and verification commands.
- Add comprehensive policy tests for every entry point.
- Add emergency-stop propagation to running subprocesses, not only pending
  approvals.
- Enforce process termination and cleanup after cancellation.


MULTI-AGENT ORCHESTRATION — 10/10
---------------------------------

- Define a formal state machine for scans, agents, phases, and tasks.
- Make every state transition validated and persisted transactionally.
- Add idempotency keys for phase and task execution.
- Add durable task queues rather than process-local queues.
- Support resume after process crash, machine reboot, Docker failure, provider
  timeout, and partial report write.
- Add bounded concurrency and backpressure.
- Add per-agent resource budgets.
- Add cancellation propagation.
- Add retry policies differentiated by failure type.
- Prevent duplicate findings across orchestrator and agent collections.
- Add deterministic ordering for findings and reports.
- Add explicit dependency graphs between phases.
- Add scan locking so two processes cannot mutate the same scan.
- Add versioned persisted-state schemas and migrations.
- Add orchestration-level integration tests with real tool fixtures.


TOOL INTEGRATIONS — 10/10
-------------------------

- Validate all options before command construction.
- Maintain a tool capability registry containing supported versions, required
  binaries, required capabilities, network requirements, output formats,
  approval level, and destructive behavior.
- Add startup preflight checks for every selected tool.
- Pin or verify tool versions.
- Add parser fixtures for multiple output versions.
- Add malformed-output and partial-output tests.
- Add stable error categories: binary missing, permission denied, timeout,
  invalid target, sandbox unavailable, parser failure, and tool failure.
- Add per-tool rate limiting and resource limits.
- Add output-size limits.
- Add process-tree cleanup on timeout.
- Add real local-target integration tests for every supported tool.
- Make tool availability visible before scan execution.
- Separate passive tools from active tools in the registry.
- Add signed or digest-pinned scanner container images.
